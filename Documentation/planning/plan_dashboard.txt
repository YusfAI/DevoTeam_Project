Objectif du projet
Ton application doit faire 3 choses très bien: comprendre la demande, choisir les bonnes données dans SQLite, puis afficher un dashboard Vega adapté. Vega est pertinent ici parce qu’il décrit les visualisations en JSON, avec la source de données, les axes, les marks, les interactions, et le rendu web.

Architecture complète
Je te recommande cette architecture en 7 blocs:

Interface web en HTML/CSS/JS.

Chat UI pour recevoir le prompt utilisateur.

LLM open source pour interpréter l’intention.

Planner JSON pour structurer la demande.

SQL generator pour interroger SQLite.

Vega generator pour produire le dashboard.

Renderer web pour afficher le résultat.

Pipeline de fonctionnement
Le flux idéal est le suivant:

L’utilisateur écrit: “Je veux suivre les ventes par mois et filtrer par pays”.

Le LLM extrait l’intention: métrique = ventes, temps = mois, filtre = pays.

Le système vérifie quelles tables SQLite contiennent ces champs.

Un module construit une requête SQL sur SQLite.

Les résultats sont récupérés.

Un générateur crée une spec Vega.

Le dashboard s’affiche dans le navigateur.
vega
+1

Ce pipeline est plus robuste que de demander au LLM de générer un dashboard complet en une seule fois, car Vega attend une structure précise et SQLite demande des requêtes cohérentes avec le schéma réel.

Structure SQLite
Je te conseille de séparer SQLite en tables claires:

users: comptes ou sessions.

prompts: texte utilisateur et métadonnées.

dashboard_requests: intention extraite, métriques, filtres.

datasets: description des sources de données.

facts: données principales.

dimensions: pays, mois, produit, catégorie.

generated_dashboards: spec Vega sauvegardée.

logs: erreurs, performance, validation.

Format intermédiaire recommandé
Au lieu de passer du prompt directement à Vega, crée un JSON intermédiaire. Par exemple:

json

{
  "goal": "analyser les ventes",
  "metric": "sales",
  "dimension": "month",
  "filters": ["country"],
  "chart_type": "line",
  "aggregation": "sum",
  "time_range": "all"
}
Ce JSON intermédiaire devient le contrat entre le LLM et ton moteur Vega. Vega peut ensuite utiliser les données chargées depuis SQLite via SQL ou via un dataset préparé.

Choix du LLM
Pour le meilleur rendu, choisis un modèle open source capable de sortie structurée, de raisonnement correct, et de génération de JSON propre. Ce qui compte le plus ici, ce n’est pas seulement la “puissance”, mais la stabilité sur les tâches de transformation d’intention en structure technique.

Règles de conception
Ne laisse jamais le LLM écrire du SQL libre sans contrôle. Utilise une liste blanche de tables et de colonnes autorisées. C’est important pour éviter les erreurs et garder un système stable sur SQLite.
